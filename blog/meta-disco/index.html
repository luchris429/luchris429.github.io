TL;DR

We can leverage recent advancements in JAX to train RL agents 1000x faster. This lets us do some pretty cool things. The code is here: https://github.com/luchris429/FastJaxRL

Overview

This blog post is about a new computational and experimental paradigm that powers many recent and ongoing works at the Foerster Lab for AI Research (FLAIR) that we call "Discovery via Accelerated Evolutionary Meta-Learning (AEML)". The techniques that power this paradigm have the potential to radically accelerate the rate of progress in Deep Reinforcement Learning (RL) algorithms by more heavily utilising GPU resources, enabled by recent advancements in JAX. AEML vastly lowers the computational barrier of entry to Deep RL research, enabling academic labs to perform research using trillions of frames (closing the gap with industry research labs) and enabling independent researchers to get orders of magnitude more mileage out of limited hardware.

This blog post will be roughly split into two parts. The first will be about the computational techniques that enable this paradigm, and the second will be about how we can effectively leverage these techniques to deepen our understanding of RL agents and algorithms with meta-learning. We will then briefly describe three recent papers from our lab that utilised this framework to great extent:

  • Model-Free Opponent Shaping
  • Discovered Policy Optimisation
  • Adversarial Cheap Talk

Part 1: Accelerating Reinforcement Learning with JAX

Section 1.1: Run Everything on the GPU!

Most Deep RL implementations run on a combination of CPU and GPU resources. Usually, the environments run on the CPU while the policy neural network and algorithms run on the GPU. Oftentimes, to increase the wallclock time, practitioners will run multiple environments in parallel using multiple threads. For reference, we will look at Costa Huang's amazing CleanRL library for an example of a well-benchmarked implementation of PPO.

Instead of using multiple threads for our environment, we can use Jax to easily vectorise the environment on the GPU! If we program our environment using Jax primitives, we can use Jax's amazing vmap function to instantly create a vectorised version of the environment. This means that the environments run in parallel on the GPU! Luckily for us, there are a few libraries that have already done this for us for a variety of RL environments!

There are a few libraries that we highly recommend and complement each other well:

  • Gymnax is an awesome library that contains several well-known environments such as Classic Control tasks, Bsuite tasks, and Minatar (atari-like) environments. I use it as the go-to library for testing and evaluating my code, and is the one we will be using for this blog post. It has a lot of other really neat features (such as vmappable environment configs!!!) and is very easy to use.
  • Brax is the way to run Mujoco-like continuous control environments using Jax. The library has many RL environments that are directly analogous to popular continuous control environments, such as HalfCheetah and Humanoid. It's also differentiable!
    •
  • Jumanji contains a lot of incredibly cool, simple, and industry-driven environments. Many of the environments in this library come directly from industry settings, ensuring that the environments presented here are practical and relevant for the real-world! These include combinatorial problems such as the famous Traveling Salesman Problem or 3D Bin Packing.
    •

Let's take a look at some of the reported speedups for Gymnax below. CartPole-v1 in numpy, with 10 environments running in parallel, takes 46 seconds to reach one million frames frames. Using Gymnax on an A100, with 2k environments in parallel, it takes 0.05 seconds. That's a 1000x speedup. This applies to environments more complicated than CartPole-v1 as well. For example, Minatar-Breakout, which takes 50 seconds to reach one million frames on CPU only takes 0.2 seconds in Gymnax. These results show an improvement of several orders of magnitude, enabling academic researchers to easily run experiments that potentially involve trillions of frames on limited hardware.

Due to Amdahl's Law, this unfortunately does not equate to a 1000x speedup in training time. However, it does mean that we can run many more environments in parallel, which can lead to alternative training paradigms for RL. For example, Brax's PPO implementation runs 2048 environments in parallel with a short rollout length of 5. This is nearly the exact opposite of OpenAI Baseline's impelementation that runs a single environment with a rollout length of 2048. While Brax's PPO ultimately ends up being less sample efficient, it runs significantly faster. However, this type of wallclock speedup is not what this blog post is mainly about.

There are many other advantages to doing everything end-to-end in Jax beyond just pure vectorisation. To name a few:

  • By keeping the computation entirely on the GPU, we avoid the overhead of copying data back and forth between the CPU and GPU, which is often a significant bottleneck.
  • By JIT compiling our implementation, we can avoid the overhead of Python, which can sometimes block GPU computation between sending commands.
  • JIT-compilation can lead to significant speedups through operator fusion
  • It is fully synchronous. Multi-processing for running environments in parallel is notoriously difficult to debug and leads to complicated infrastructure.

    • To demonstrate this, we closely replicated CleanRL's PyTorch PPO baseline implementation in pure Jax and jitted it end-to-end. We used the same number of parallel environments and the same hyperparameter settings, so we're not taking advantage of the massive environment vectorisation. We show the training plots below across 5 runs in CartPole-v1 and MinAtar-Breakout.

    Section 1.2: Running Many Agents in Parallel

    We got a pretty good speedup from the above tricks. However, it's far from the 1000x speedup in the headline. How do we get there? By vectorising the entire RL training loop. This is really easy to do! Just use Jax's vmap we mentioned before! Now we can train many agents in parallel! Furthermore, to run on multiple GPU's we can just use Jax's convenient pmap function! Previously, this type of vectorisation both across and especially within devices would have been a massive headache to write (believe me, I've tried).

    That's more like it! If you're developing a new RL algorithm, you can easily train on a statistically-significant number of seeds simultaneously on a single GPU. Beyond that, we can we can easily train thousands of agents at the same time! Why would we want to do that?

    Part 2: Discovery via Long-Horizon Evolutionary Meta-Learning

    Very fast, convenient, and parallelisable RL training enables a new meta-learning framework that we use at FLAIR to better analyse and understand the behavior of RL algorithms and agents. We call this framework "Discovery via Meta-Evolution".

    Meta-Learning is the idea of "Learning to Learn". A very popular approach to do this is through using meta-gradients, or higher-order derivatives. In essence, these methods, the most well-known of which is MAML, take derivativies through their own learning updates. Using these types of techniques, we can optimise our parameters to take into account learning updates, which can then be used to quickly adapt to new tasks. Usually, this is taken in the context of fast adaptation, in which we train models that are able to quickly adapt to similar, but unseen tasks with just a small number of samples. While this is useful for a narrow domains, ideally we would like to be able to meta-learn more general purpose learning algorithms and principles that can be more widely applied to a large range of tasks across many updates.

    However, if we want to learn to learn across a wide range of tasks, we need to be able to meta-learn across a large number of interactions. In the case of meta-learning RL algorithms, we need to meta-learn across millions of timesteps and thousands of updates. Many papers have shown that gradient-based methods do not perform well in this setting because they result in high variance updates. CITE. Approaches that attempt to reduce this variance tend to increase bias.

    Alternatively, we can use evolutionary methods to meta-learn across these long horizons. These methods don't take explicit derivatives through their parameters and instead treat the underlying problem as a blackbox. If you want to learn more about these methods, we highly recommend David Ha's beautiful blog post on the topic. There are a few reasons these methods are very attractive for this setting. ES methods are:

  • Agnostic to the number of learning timesteps
  • Not concerned with vanishing or exploding gradients
  • Unbiased
  • Lower variance
  • Highly parallelisable

    • At a high level, this is analogous to emergence of learning in real-world evolution -- animals genetically evolved the ability to perform reinforcement learning in their brains.

    One of the primary criticisms against these methods is that, although they are parallelisable, they are extremely slow and sample inefficient, and usually require the ability to sample thousands of agents at the same time. If only there was a way to efficiently do this!

    A very nice library for doing this is evosax. We can easily hook up our RL training loop to this library and use it to perform extremely fast meta-evolution entirely on the GPU. Here's a simple example where we meta-learn the value loss function of a PPO agent on the CartPole-v1.

    To summarise, this discovery framework involves:

  • Running everything on the GPU by using Jax.
  • Meta-Learning across entire training trajectories with evolutionary methods.
  • Interperting the learned meta-parameters to "discover" new insights about learning algorithms.

    • Part 3: Case Studies

    This is a very powerful framework that we use at FLAIR to better understand the behavior of RL algorithms and have used it in several published papers, which we will briefly describe below:

    Discovered Policy Optimisation

    Link

    What we meta-learned: Many existing RL algorithms can be described by a theoretical framework called "Mirror Learning". We parameterise part of this space of algorithms with a neural network and meta-learn it to discover a new algorithm that outperforms existing ones!

    What we visualised: We visualised what the learned loss function (LPO) looked like with respect to the inputs.

    What we discovered: LPO rediscovers past ideas in the literature, like notions of rollback and optimism, along with some novel features, which we combine to create a closed-form analytical version of the algorithm we call DPO that outperforms PPO on unseen tasks.

    Adversarial Cheap Talk

    Link

    What we meta-learned: We append deterministic features to existing RL environments and show that we can cause RL algorithms to completely fail or perform better, even though simply appending features should not influence the underlying dynamics or optimal policy. In theory the RL agent should be able to ignore the appended inputs!

    What we visualised: We visualised the cosine distance between gradient updates in different parts of the environment. This has previously been used to measure notions of catastrophic interference.

    What we discovered:Adversarial ACT works by learning to induce catastrophic interference in the learning agent's function approximator. In other words, gradient updates taken at the beginning steps of the environment interfere and cancel out with gradient steps taken at the ending steps of the environment. Allied ACT works by doing the exact opposite way: The gradient steps taken at different parts of the environment are positively correlated, meaning that gradients for steps taken in the beginning help performance at the steps at the end of the episode!

    Something Extra in the Paper: We also meta-learned an adversary that learns to encode spurious correlations over the cheap talk channel during training, and then instantly leverage the cheap talk channel at test time to achieve an arbitrary goal! In the gif below, the agent is trained to reach for the blue circle with a given cheap talk channel. At test time, when the cheap talk channel is swapped out, the agent ends up reaching for the yellow one!

    Model-Free Opponent Shaping

    Link

    What we meta-learned: Behaving in the presence of other learning opponents is hard. Existing methods like LOLA use a special update rule to account for the opponent's learning and "shape" them. We instead reformulate this as a meta-learning problem to discover this update rule we call M-FOS.

    What we visualised: We visualised how the policy behaves in the iterated prisoner's dilemma against a learning opponent.

    What we discovered:M-FOS influences the long-term evolution of the opponent's policy and far outperforms existing learning algorithms. The visualisation above shows that it does this by discovering a policy that is closely related to a sophisticated policy called ZD-Extortion.
